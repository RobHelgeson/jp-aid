# Story 2.2: Kanji Ordering

**Status:** Done

**Story**
As a user, I want the extracted kanji to be presented in the order they appear in the input, so that the context of the original sentence is preserved.

**Acceptance Criteria (ACs)**

1. The output list of kanji matches the order of appearance in the input.
2. If a kanji appears multiple times, only the first occurrence is kept.
3. The order is preserved when passing data to the results/detail screens.

## Implementation Status Summary

Story 2.1 implemented most of the ordering functionality. Here is the current state:

### Already Implemented (AC1 & AC2 Complete)

- **TextParsingService.extractKanji()** (`apps/jp-aid/src/app/services/text-parsing/text-parsing.service.ts`)
  - Returns kanji in order of first appearance (uses `preserveOrder: true` by default)
  - Removes duplicates while keeping first occurrence (uses `removeDuplicates: true` by default)
  - Comprehensive tests exist in `text-parsing.service.spec.ts` with 30+ test cases

- **MockData.getKanjiByIds()** (`apps/jp-aid/src/app/services/mock-data.service.ts`)
  - Preserves input order when returning kanji objects
  - Tests exist verifying order preservation

- **KanjiResults.filteredKanji()** (`apps/jp-aid/src/app/kanji-results/kanji-results.ts`)
  - Calls `textParsingService.extractKanji()` then `mockData.getKanjiByIds()`
  - Order is preserved through the display pipeline

### Remaining Work (AC3 Gap)

- **Navigation Context Not Set**: When user clicks a kanji in KanjiResults, the component navigates to KanjiDetail but does NOT pass the ordered search results context.
- **KanjiDetail Uses Wrong Order**: `KanjiDetail.ngOnInit()` uses `allKanji.slice(0, 10)` instead of the actual ordered results from the search.
- **Impact**: Previous/Next navigation in KanjiDetail does not respect the user's text input order.

## Dev Technical Guidance

### Code Changes Required

1. **KanjiResults Component** (`apps/jp-aid/src/app/kanji-results/kanji-results.ts`)
