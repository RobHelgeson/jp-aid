# Story 2.5: Multi-Word Support

**Status:** Done

**Story**
As a user, I want the system to handle multiple words or sentences gracefully, so that I can extract kanji from all input and see results grouped logically.

**Acceptance Criteria (ACs)**

1. The system extracts kanji from all words/sentences in the input.
2. Results are grouped or annotated by word/sentence if possible.
3. The UI supports displaying grouped results.

### Implementation Approach

This story adds **text segmentation** - breaking input into logical segments (words, sentences, or phrases) and tracking which kanji came from which segment. This enables:

- Grouping kanji results by their source segment
- Showing context for each kanji (the word/sentence it came from)
- Better UX for multi-sentence input like study sentences or paragraphs

### Key Design Decisions

1. **Segmentation Strategy**: Use Japanese punctuation and whitespace as natural delimiters:
   - Sentence delimiters: `。` (period), `！` (exclamation), `？` (question), `\n` (newline)
   - Phrase delimiters: `、` (comma), `・` (interpunct), spaces
   - A "segment" is defined as text between delimiters containing at least one kanji

2. **Segment Hierarchy**: Support two levels of grouping:
   - **Sentences**: Split on sentence-ending punctuation (。！？\n)
   - **Segments within sentences**: Further split on commas/spaces if needed

3. **Opt-in Grouping**: Grouping is triggered only when input contains segmentation markers. Single-word input behaves exactly as before (backward compatible).

4. **Preserve Existing Behavior**: All existing methods continue to work unchanged. New functionality is additive.

### Data Models & Interfaces

Add to `libs/shared-interfaces/src/lib/text-parsing.ts`:

```typescript
/**
 * Represents a segment of text (word, phrase, or sentence) with its kanji
 */
export interface TextSegment {
  /** The original text of this segment */
  text: string;
  /** Zero-based start position of this segment in the original input */
  startPosition: number;
  /** Zero-based end position (exclusive) of this segment */
  endPosition: number;
  /** Unique kanji characters found in this segment (ordered by first appearance) */
  kanji: string[];
  /** Position data for each kanji in this segment */
  kanjiPositions: KanjiPosition[];
  /** Index of this segment (0-based) */
  segmentIndex: number;
}

/**
 * Result of parsing text with segment grouping
 */
export interface SegmentedParsingResult extends TextParsingResultWithPositions {
  /** Whether the input was segmented (has multiple segments) */
  isSegmented: boolean;
  /** Array of text segments, each containing its kanji */
  segments: TextSegment[];
  /** Total number of segments */
  segmentCount: number;
}

/**
 * Options for text segmentation behavior
 */
export interface SegmentationOptions extends KanjiExtractionOptions {
  /** Enable sentence-level segmentation on 。！？\n (default: true) */
  segmentBySentence?: boolean;
  /** Enable phrase-level segmentation on 、・ and spaces (default: false) */
  segmentByPhrase?: boolean;
  /** Minimum segment length to include (default: 1) */
  minSegmentLength?: number;
  /** Include empty segments in output (default: false) */
  includeEmptySegments?: boolean;
}
```

### Service Implementation

Extend `TextParsingService` with new methods:

```typescript
/**
 * Parses text and groups kanji by segment (sentence or phrase)
 * @param text The text to parse
 * @param options Segmentation options
 * @returns SegmentedParsingResult with kanji grouped by segment
 */
parseTextWithSegments(text: string, options: SegmentationOptions = {}): SegmentedParsingResult

/**
 * Splits text into segments based on Japanese punctuation
 * @param text The text to split
 * @param options Segmentation options
 * @returns Array of raw text segments with positions
 */
private segmentText(text: string, options: SegmentationOptions): Array<{text: string, start: number, end: number}>
```

**Algorithm for `parseTextWithSegments()`**:

1. If text is empty or has no segmentation markers, return single-segment result
2. Split text using regex based on `segmentBySentence` and `segmentByPhrase` options
3. For each segment:
   - Track start/end positions relative to original text
   - Extract kanji with positions (relative to segment start)
   - Adjust positions to be relative to original text
4. Build `SegmentedParsingResult` aggregating all segment data

**Segmentation Regex Patterns**:
- Sentence delimiters: `/([。！？\n]+)/` (capturing to preserve delimiter position)
- Phrase delimiters: `/([、・\s]+)/`
- Combined: `/([。！？\n、・\s]+)/`

### UI Changes

#### 1. ResultsPage Updates

Add new computed signals for segmented display:

```typescript
protected segmentedResult = computed(() => {
  const query = this.searchQuery();
  if (!query) return null;
  return this.textParsingService.parseTextWithSegments(query);
});

protected hasSegments = computed(() => {
  const result = this.segmentedResult();
  return result?.isSegmented ?? false;
});

protected displayMode = computed((): 'grouped' | 'flat' => {
  return this.hasSegments() ? 'grouped' : 'flat';
});
```

### Edge Cases to Handle

1. **Trailing delimiters**: "日本語。" should produce one segment, not two
2. **Multiple consecutive delimiters**: "日本。。。中国" should produce two segments
3. **Mixed delimiters**: "日本！？中国" should produce two segments
4. **Empty segments**: "。日本。" should skip empty first segment
5. **Whitespace handling**: Trim segments but preserve original positions
6. **Large input**: Ensure performance for long text (>1000 characters)

### UI/UX Considerations

1. **Segment Header Truncation**: Long segment text should be truncated with ellipsis and show full text on hover (title attribute)
2. **Segment Collapse**: Future enhancement - allow collapsing segment groups
3. **Segment Navigation**: Consider adding "Jump to segment" links for long multi-segment input
4. **Mobile Layout**: Segment headers should stack vertically on narrow screens
5. **Empty Segments**: Don't display segments that have no kanji (filter in template)
