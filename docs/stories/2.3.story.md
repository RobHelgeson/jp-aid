# Story 2.3: Kanji Mapping

**Status:** Done

**Story**
As a user, I want to see each kanji's position in the original text, so that I can relate the kanji to its usage in the sentence.

**Acceptance Criteria (ACs)**

1. Each extracted kanji is mapped to its index/position in the input.
2. The mapping is available to the UI for highlighting or reference.
3. The mapping supports multi-kanji and multi-sentence input.

## Dev Technical Guidance

### Context from Previous Stories

Story 2.1 established the `TextParsingService` with core extraction methods:
- `extractKanji(text, options)` - Returns unique kanji in order of first appearance
- `isKanji(char)` - Validates if a character is kanji
- `containsKanji(text)` - Quick check for kanji presence
- `parseText(text, options)` - Returns `TextParsingResult`

Story 2.2 ensured ordering is preserved through the UI pipeline:
- `filteredKanji()` in KanjiResults maintains order
- `MockData.getKanjiByIds()` preserves input order
- Navigation context passes ordered results to KanjiDetail

### Implementation Approach

This story adds **position mapping** - tracking WHERE each kanji appears (all occurrences) in the original text. This enables UI features like:
- Highlighting kanji in the original text
- Showing position context (e.g., "appears at positions 0, 5, 12")
- Future: sentence segmentation with per-sentence kanji positions

### Key Design Decisions

1. **Track All Occurrences**: While `extractKanji()` returns unique kanji, the mapping should track ALL positions where each kanji appears (for future highlighting).

2. **Position Format**: Use zero-based character indices matching JavaScript string indexing.

3. **Multi-Sentence Support**: The mapping should work with any text length; sentence segmentation is deferred to Story 2.5.

### Data Models & Interfaces

Add to `libs/shared-interfaces/src/lib/text-parsing.ts`:

```typescript
/**
 * Position information for a kanji character in the original text
 */
export interface KanjiPosition {
  /** The kanji character */
  kanji: string;
  /** Zero-based index positions where this kanji appears in the original text */
  positions: number[];
  /** Index of first occurrence (for ordering) */
  firstPosition: number;
}

/**
 * Extended parsing result with position mapping
 */
export interface TextParsingResultWithPositions extends TextParsingResult {
  /** Map of kanji to their positions in the original text */
  kanjiPositions: KanjiPosition[];
}
```

### Service Implementation

Extend `TextParsingService` with a new method:

```typescript
/**
 * Extracts kanji with position mapping
 * @param text The text to parse
 * @param options Optional extraction options
 * @returns TextParsingResultWithPositions with kanji and their positions
 */
extractKanjiWithPositions(text: string, options: KanjiExtractionOptions = {}): TextParsingResultWithPositions
```

**Algorithm**:
1. Iterate through each character in the text
2. For each kanji found, record its position
3. Group positions by kanji character
4. Sort the result by first occurrence (to match existing ordering behavior)

### Integration Points

1. **TextParsingService**: Add `extractKanjiWithPositions()` method
2. **TextParsingResult Interface**: Extend with position data
3. **KanjiResults Component**: Optionally expose positions for future highlighting features
4. **No UI Changes Required**: This story focuses on data availability; UI highlighting is a future enhancement
