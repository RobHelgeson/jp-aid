# Story 2.4: Non-Kanji Handling

**Status:** Done

**Story**
As a user, I want a clear message if my input contains no kanji, or if the kanji found are not in the database, so that I know why no results are shown and what to do next.

**Acceptance Criteria (ACs)**

1. If no kanji are found in the input, a user-friendly message is displayed (e.g., "No kanji found in your input. Please try again.").
2. If kanji are found in the input but none are present in the database, a different message is displayed (e.g., "No information available for the kanji you entered. Please try different text or check back later.").
3. If some kanji are found and some are missing from the database, the UI displays available results and clearly indicates which kanji could not be found.
4. All error and info messages are clear, actionable, and do not block further input.

  - No handling for partial matches or missing kanji feedback

### Implementation Approach

This story enhances user feedback by distinguishing between three distinct states:

1. **No Kanji in Input**: User entered text without kanji characters (hiragana, katakana, Latin, symbols)
2. **Kanji Not in Database**: User entered kanji characters, but none exist in our database
3. **Partial Match**: Some kanji found, some missing from database - show results with notice

### Data Models & Interfaces

Add to `libs/shared-interfaces/src/lib/text-parsing.ts`:

```typescript
/**
 * Detailed result status for kanji search operations
 */
export enum KanjiSearchStatus {
  /** Kanji found and all are in database */
  FOUND = 'found',
  /** No kanji characters in input text */
  NO_KANJI_IN_INPUT = 'no_kanji_in_input',
  /** Kanji found but none are in database */
  KANJI_NOT_IN_DATABASE = 'kanji_not_in_database',
  /** Some kanji found, some missing from database */
  PARTIAL_MATCH = 'partial_match'
}

/**
 * Extended search result with status and missing kanji information
 */
export interface KanjiSearchResult {
  /** Status of the search operation */
  status: KanjiSearchStatus;
  /** Kanji characters extracted from input */
  extractedKanji: string[];
  /** Kanji characters found in database */
  foundKanji: string[];
  /** Kanji characters not found in database */
  missingKanji: string[];
  /** Original search text */
  originalText: string;
}
```

### UI Message Guidelines

Messages should be:
- Clear and specific about what happened
- Actionable (tell user what to try next)
- Non-blocking (user can immediately try another search)
- Accessible (proper ARIA attributes, semantic HTML)

| Status | Message | Icon | Style |
|--------|---------|------|-------|
| `NO_KANJI_IN_INPUT` | "No kanji characters found in your input. Try entering Japanese text containing kanji, or search by meaning or reading." | `info` | Info banner (blue) |
| `KANJI_NOT_IN_DATABASE` | "The kanji you entered (漢, 字) are not yet in our database. Try different kanji or check back later as we add more." | `warning` | Warning banner (amber) |
| `PARTIAL_MATCH` | "Found X of Y kanji. The following are not yet in our database: 漢, 字" | `info` | Info notice (subtle) |

### Component Changes

#### 1. ResultsPage Component (`apps/jp-aid/src/app/results-page/`)

Add computed signals to determine search status:

```typescript
protected searchStatus = computed((): KanjiSearchStatus => {
  const searchText = this.searchQuery().trim();
  if (!searchText) {
    return KanjiSearchStatus.NO_KANJI_IN_INPUT;
  }

  const extracted = this.extractedKanji();
  if (extracted.length === 0) {
    return KanjiSearchStatus.NO_KANJI_IN_INPUT;
  }

  const matchingKanji = this.mockData.getKanjiByIds(extracted);
  if (matchingKanji.length === 0) {
    return KanjiSearchStatus.KANJI_NOT_IN_DATABASE;
  }

  if (matchingKanji.length < extracted.length) {
    return KanjiSearchStatus.PARTIAL_MATCH;
  }

  return KanjiSearchStatus.FOUND;
});

protected missingKanji = computed((): string[] => {
  const extracted = this.extractedKanji();
  const found = this.mockData.getKanjiByIds(extracted);
  const foundIds = new Set(found.map(k => k.id));
  return extracted.filter(k => !foundIds.has(k));
});
```

#### 2. Template Updates (`apps/jp-aid/src/app/results-page/results-page.html`)

Replace simple `@if (hasResults())` with status-based rendering:

```html
@switch (searchStatus()) {
  @case ('found') {
    <section class="results-section" aria-label="Found kanji">
      <kl-kanji-results [searchText]="searchQuery()" />
    </section>
  }
  @case ('partial_match') {
    <div class="partial-match-notice" role="status" aria-live="polite">
      <mat-icon>info</mat-icon>
      <span>Found {{ foundKanjiCount() }} of {{ extractedKanji().length }} kanji.
        Not in database: {{ missingKanji().join(', ') }}</span>
    </div>
    <section class="results-section" aria-label="Found kanji">
      <kl-kanji-results [searchText]="searchQuery()" />
    </section>
  }
  @case ('no_kanji_in_input') {
    <section class="no-results info-state" role="status" aria-live="polite">
      <mat-icon class="status-icon">translate</mat-icon>
      <h2>No Kanji Found</h2>
      <p>No kanji characters found in your input.</p>
      <p class="suggestion">Try entering Japanese text containing kanji, or search by meaning or reading.</p>
      <button mat-raised-button color="primary" (click)="goBackToSearch()">
        Try Another Search
      </button>
    </section>
  }
  @case ('kanji_not_in_database') {
    <section class="no-results warning-state" role="status" aria-live="polite">
      <mat-icon class="status-icon">search_off</mat-icon>
      <h2>Kanji Not Available</h2>
      <p>The kanji you entered ({{ extractedKanji().join(', ') }}) are not yet in our database.</p>
      <p class="suggestion">Try different kanji or check back later as we expand our collection.</p>
      <button mat-raised-button color="primary" (click)="goBackToSearch()">
        Try Another Search
      </button>
    </section>
  }
}
```
