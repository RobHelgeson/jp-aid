# Story 2.1: Text Parsing

**Status:** Not Started

**Story**
As a user, I want the system to correctly identify and extract only the unique kanji characters from my input, so that I can focus on the kanji present in any word or sentence.

**Acceptance Criteria (ACs)**

1. The system accepts any Japanese text input (word, sentence, phrase).
2. Only kanji characters are extracted; kana, punctuation, and duplicates are ignored.
3. Extraction is accurate for mixed-content input (kanji, kana, Latin, symbols).
4. The extracted kanji are passed to the next processing step.

**Dev Technical Guidance**

* **Previous Story Insights**: Story 1.9 implemented graph interaction and node traversal functionality. The GraphService now supports advanced exploration patterns and state management.
* **Text Parsing Implementation**:
  * **Input Handling**: Create a new service or extend existing services to handle Japanese text input processing
  * **Kanji Extraction Logic**: Implement regex-based kanji extraction that handles mixed content and ignores non-kanji characters
  * **Duplicate Removal**: Ensure only unique kanji are returned from the extraction process
* **Data Models & Interfaces**:
  * **Text Parsing Interface**: Define interfaces for input processing and kanji extraction results
  * **Extraction Service**: Create a dedicated service for text parsing or extend existing services
* **Component Architecture**:
  * **Input Component**: Extend search page or create new input component for Japanese text entry
  * **Results Integration**: Ensure extracted kanji are properly passed to results and detail components
* **UI Component Library & Styling**:
  * **Angular Material**: Maintain consistency with existing Material Design components

* **Service Enhancement**:
  * **Text Parsing Methods**: Add methods to handle input processing and kanji extraction
