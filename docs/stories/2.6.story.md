# Story 2.6: Integration with UI

**Status:** Done

**Story**
As a user, I want the extracted kanji to be passed seamlessly to the results and detail screens, so that my experience is smooth and uninterrupted.

**Acceptance Criteria (ACs)**

1. Extracted kanji are passed to the results screen without loss or reordering.
2. The transition from input to results/detail is smooth and fast.
3. The UI updates correctly for all valid and invalid input cases.

## Dev Technical Guidance

### Context from Previous Stories

This is the **FINAL story for Epic 2**. Stories 2.1-2.5 established the complete text parsing infrastructure:

- **Story 2.1 - Text Parsing**: `TextParsingService` with `extractKanji()`, `containsKanji()`, `parseText()`
- **Story 2.2 - Kanji Ordering**: Order preservation using first-appearance ordering
- **Story 2.3 - Kanji Mapping**: `extractKanjiWithPositions()` for position tracking
- **Story 2.4 - Non-Kanji Handling**: `KanjiSearchStatus` enum with four states (FOUND, NO_KANJI_IN_INPUT, KANJI_NOT_IN_DATABASE, PARTIAL_MATCH)
- **Story 2.5 - Multi-Word Support**: `parseTextWithSegments()` for grouped display

### Implementation Approach

This story focuses on **integration verification and polish** rather than new features:

1. **Verify Order Preservation** (AC1): Ensure kanji order is maintained from input through all screens
2. **Transition Polish** (AC2): Audit animations, loading states, reduce artificial delays
3. **Complete State Coverage** (AC3): Verify all KanjiSearchStatus states render correctly
4. **E2E Test Suite** (AC1, AC2, AC3): Comprehensive Playwright tests for Epic 2 flows

### Order Preservation Verification

The current implementation maintains order through:

1. `TextParsingService.extractKanji()` - Returns kanji in first-appearance order
2. `MockData.getKanjiByIds()` - Returns kanji in the order of the input IDs array
3. `KanjiResults.filteredKanji` - Uses `getKanjiByIds()` preserving order
4. `MockData.setSearchResults()` - Stores ordered array for prev/next navigation

**Verification Points:**

- Input: "日本語" should produce results in order: 日, 本, 語
- Detail page prev/next should follow this order
- Multi-sentence input should preserve intra-segment order

### Transition Performance Audit

**Current Implementation:**

- `ResultsPage.performSearch()` has 800ms artificial delay (line 99-103)
- Animations use 400ms duration (page-transitions.ts)
- Loading spinner has enter/leave animations (300ms each)

**Polish Opportunities:**

1. **Reduce Artificial Delay**: Consider reducing 800ms to 300-400ms for snappier UX
2. **Skeleton Loading**: Consider skeleton states instead of spinner for perceived performance
3. **Optimistic UI**: Show results immediately when coming from KanjiResults
4. **Reduced Motion**: Verify `prefers-reduced-motion` is respected
