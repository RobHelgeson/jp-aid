# Story 1.2.1: UI Polish and Layout Catch-up

**Status:** Done

**Story**
As a developer, I need to implement the final layout for the search screen and add the required interactive states for the results cards to match the UI specification before proceeding to the next feature.

**Acceptance Criteria (ACs)**

1. The `kanji-search` component is centered vertically and horizontally on the main application page, mimicking the minimalist ChatGPT-style layout.
2. The `kanji-results` cards have a distinct visual style for hover state.
3. The `kanji-results` cards have a distinct visual style for active/selected state.
4. Unit tests are created to verify the hover and active/selected states of the cards.

**Dev Technical Guidance**

* **Source of Truth**: All visual and UX decisions must adhere to the **[front-end-spec.md](</Users/rvh/Documents/Code/jp-aid/docs/front-end-spec.md)**.
* **Previous Story Insights**: This story addresses the incomplete layout and styling tasks from stories 1.1 and 1.2.
* **Component Specifications**:
  * **Search Screen Layout**: The main app view should be updated to center the `app-kanji-search` component. Use Flexbox or CSS Grid to achieve the centered layout as described in the wireframe. [Source: front-end-spec.md#search-screen]
  * **Kanji Card States**: Implement CSS classes for `.kanji-card:hover` and a new class, `.kanji-card.active`, for the selected state. The styles should provide clear visual feedback. [Source: front-end-spec.md#kanji-list-item]
* **Testing Requirements**:
  * Update or create unit tests for the `kanji-results` component to verify that the correct CSS classes are applied on hover and click events.

**Tasks / Subtasks**

1. **[x] (AC: 1)** Modify the main application layout (`app.html` and `app.scss`) to center the `app-kanji-search` component on the page.
2. **[x] (AC: 2)** In `kanji-results.scss`, add CSS rules for the `:hover` pseudo-class on the `mat-card` to change its appearance (e.g., background color, box-shadow).
3. **[x] (AC: 3)** In `kanji-results.ts`, add logic to track the currently selected card. On click, apply an `.active` class to the selected card.
4. **[x] (AC: 3)** In `kanji-results.scss`, add CSS rules for the `.active` class to give the selected card a distinct, persistent style (e.g., a border or different background color).
5. **[x] (AC: 4)** Create new unit tests in `kanji-results.spec.ts` to:
    * Simulate a click on a card and verify the `.active` class is applied.
    * Simulate a click on a different card and verify the `.active` class is moved correctly.

**Project Structure Notes**
No new files need to be created, only modifications to existing component files are expected.
