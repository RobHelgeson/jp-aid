# Story 1.2.2: Search to Results Page Navigation & Animation

**Status:** Done

**Story**
As a learner, I want the search experience to be more engaging and visually appealing, with the search page having a larger search input and smooth animations that transition me from the search page to a dedicated results page.

**Acceptance Criteria (ACs)**

1. The search page has a larger, more prominent search input with bigger font, vertically centered on the page.
2. When search is submitted, the search page animates up and out of the viewport.
3. A results page is created that displays the search results with a loading spinner.
4. During search processing, an interstitial spinner animates up from the bottom of the viewport.
5. When results are ready, the spinner animates up out of the top and the results page animates in from the bottom.
6. The results page has a distinct URL pattern `/search?q={query}` that supports bookmarking and browser history.
7. All animations respect accessibility preferences (`prefers-reduced-motion`).

**Dev Technical Guidance**

* **Source of Truth**: All visual and UX decisions must adhere to the **front-end-spec.md** and Angular animation patterns.
* **Previous Story Insights**: Story 1.2.1 implemented centered search layout and interactive results cards. This story refactors the architecture to separate search and results into distinct pages.
* **Current Architecture Impact**: The existing `app.html` template currently displays both search and results components together. This needs to be refactored into a routing-based approach.
* **Animation Requirements**:
  * **Framework**: Angular Animations (`@angular/animations`) [Source: architecture/tech-stack.md#frontend-framework]
  * **BrowserAnimationsModule**: Must be imported in app configuration [Source: architecture/tech-stack.md#frontend-framework]
  * **Timing**: Smooth transitions (~300-500ms) with natural easing curves
  * **Accessibility**: Respect `prefers-reduced-motion` media query [Source: architecture/coding-standards.md#accessibility]
* **Routing Architecture**:
  * **Search Page**: Root route `/` with enhanced search interface [Source: front-end-spec.md#navigation-structure]
  * **Results Page**: Route `/search?q={query}` with animated entry [Source: front-end-spec.md#navigation-structure]
  * **Query Parameters**: Use Angular Router's query parameters for search state
* **Component Specifications**:
  * **Search Page Component**: New `kl-search-page` component with enhanced search input [Source: architecture/coding-standards.md#angular-preferences]
  * **Results Page Component**: New `kl-results-page` component containing kanji results [Source: architecture/coding-standards.md#angular-preferences]
  * **Spinner Component**: Reusable `kl-loading-spinner` component with animation [Source: architecture/coding-standards.md#shared-libraries]
* **Data Flow**:
  * **Search Submission**: Navigate to results page with query parameter
  * **Results Loading**: Show spinner during mock data retrieval
  * **State Management**: Use Angular services for search state [Source: architecture/application-architecture.md#state-management]
* **File Locations**:
  * **Search Page**: `apps/jp-aid/src/app/search-page/` [Source: architecture/unified-project-structure.md + architecture/coding-standards.md#angular-preferences]
  * **Results Page**: `apps/jp-aid/src/app/results-page/` [Source: architecture/unified-project-structure.md]
  * **Spinner**: `apps/jp-aid/src/app/loading-spinner/` [Source: architecture/unified-project-structure.md]
  * **Animations**: `apps/jp-aid/src/app/animations/` [Source: architecture/unified-project-structure.md]
* **Testing Requirements**:
  * **Animation Testing**: Angular TestBed with animation testing utilities [Source: architecture/testing-strategy.md#frontend-testing]
  * **Route Testing**: Test navigation and query parameter handling [Source: architecture/testing-strategy.md#unit-testing]
  * **Accessibility Testing**: Verify reduced motion preferences [Source: architecture/testing-strategy.md#unit-testing]
